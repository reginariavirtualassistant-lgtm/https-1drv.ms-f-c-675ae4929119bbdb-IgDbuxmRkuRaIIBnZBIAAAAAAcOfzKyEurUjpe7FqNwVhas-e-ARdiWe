# BronzeManna fictional issuer backend

**Never deploy this backend publicly.** This is a **local-only development simulator**, not a secure production wallet, identity provider, issuer API, token vault, or payment processor.

## Run

Requires Node.js 20+ (no dependencies):

```bash
cd backend
npm test
npm start
```

The API binds to `127.0.0.1:4200`. Test with `curl http://127.0.0.1:4200/health`.

## Demo API endpoints

- `GET /health` — no real issuer or payment capability
- `POST /v1/demo/sessions` with `{}` — creates a fictional Diana Prince session and returns a short-lived demo bearer token
- `POST /v1/issuer/link-sessions` with `{ "program":"WIC" }` — creates a fictional issuer authorization session
- `POST /v1/issuer/demo-approve` with `{ "sessionId":"...", "state":"...", "approved":true }` — simulated approval, no issuer verification
- `GET /v1/wallet/cards` — only current session's fictional links
- `GET /v1/wallet/cards/:id/benefits` — fake issuer benefits or Medicaid coverage
- `DELETE /v1/wallet/cards/:id` with `{}` — revoke fictional link
- `GET /v1/audit/events` — scoped demo audit events
- `POST /v1/demo/logout` with `{}` — end session

For protected endpoints send `Authorization: Bearer <sessionToken>`. This token is **not a real authenticated identity**. All data is in memory and disappears on server restart. The token must not be used as a production security mechanism.

## Security boundaries

- The service only binds to localhost and stores no real credentials, card numbers or recipient data.
- Request bodies are size-limited and sensitive credential field names are rejected. This is a development guardrail, not comprehensive data loss prevention.
- All issuer data is generated by `FictionalIssuerAdapter`.
- No database, HTTPS termination, real MFA/passkeys, OAuth, durable audit log, external token vault, per-client rate limits, compliance certification, or production issuer integrations exist.
- Never use this code with real recipient information or connect it to public networks.

## Production issuer adapter contract

See `src/issuer-adapter.js`. Replace `FictionalIssuerAdapter` only after an authorized agency/issuer provides approved API documentation, integration credentials, an agreement, and security/compliance approval. Issuer authentication should happen at the issuer's approved endpoint; BronzeManna must not collect EBT PINs. For payments, separate payment-rail authorization and PIN entry rules may apply.
